# Контекст проекта для следующих сессий

Перед работой прочитай `docs/README.md`, `docs/PROGRESS.md` и нужный этап `docs/ROADMAP.md`. Архитектура и принятые допущения — в `docs/ARCHITECTURE.md`, сведения о железе — в `docs/HARDWARE.md`.

Пользователь — Node.js/TypeScript разработчик (backend, web, mobile), изучающий embedded/IoT через практический проект ESP32 + датчик частиц → домашний Wi-Fi → HTTPS API на Hetzner → Telegram.

Работай на русском. Это учебный проект: объясняй новые понятия через знакомые пользователю концепции, но отмечай различия. Перед новым шагом коротко объясни цель, затем выполняй небольшой законченный шаг и помогай проверить результат. Не делай весь проект за один проход без запроса. Не считай понимание материала подтверждённым только потому, что код написан.

Текущий выбранный для плана путь: C/C++ и ESP-IDF для прошивки; Node.js/TypeScript для backend. Фреймворк backend ещё не выбран. Датчик Plantower PMS5003 подтверждён по фото IMG_1990. На фото платы видны ESP-32, CH340C, USB-C, 30 контактов; точная ревизия платы и схема не установлены. Полный инвентарь и ссылки на фото — в `docs/HARDWARE.md`. Не назначай GPIO и схему питания до проверки документации конкретной платы и распиновки шлейфа.

После содержательной работы обновляй `docs/PROGRESS.md`: что изменилось, чем проверено, что не проверено, ближайший конкретный шаг. Решения об архитектуре фиксируй в `docs/ARCHITECTURE.md`. Чекбоксы этапов отмечай только после выполнения критериев готовности. Не сохраняй секреты, SSID, пароли Wi-Fi, токены устройств и Telegram в документации или репозитории.

Если для проверки нужно физическое действие пользователя, подготовь инструкции и честно оставь проверку ожидающей. Не утверждай, что сборка, прошивка, подключение или доставка сообщения прошли успешно без свидетельств. Перед продолжением сверяй документы с фактическими файлами; устаревшие записи исправляй.
